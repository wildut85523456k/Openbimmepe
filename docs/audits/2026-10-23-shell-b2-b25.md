## B20 now uses the operation log

The first version of B20 (commit 91eb050) wrote a whole snapshot copy every 60 s. It is replaced by a journal built on
`crates/oplog`, as decided in `docs/decisions/0001-storage-model.md`: a base snapshot of the file's records and
transactions appended every 15 s that hold only the records that changed. A torn last write is dropped, a damaged one
stops the replay and the earlier work is recovered. The file is never touched, a normal Save removes the journal, and
opening a file with a newer journal asks to recover or discard it.

## Limits to know

- The Number of a room must be new on its level; a duplicate is refused.
- A pad's parent is a placed family instance only (not one in a wall).
- Named-system scope follows links, taps and fittings from the equipment; a run joined to nothing is not in any system.
- The level strip is in plans only, not in 3D, sections or on sheets.
- Rooms still do not leave in the IFC export (see the IFC bundle).
- Autosave and its dialog were not exercised in the running window, only through the functions.
