# MEP mouse-only audit of /home/claude/revit-alike (branch main, HEAD dcf8382, 2026-10-21)

Method: code reading only. I did not run cargo or any test (instruction), so "test evidence" below means a test of that name exists and I read its assertions; I did not observe it pass. Paths are relative to /home/claude/revit-alike. Docs were treated as claims to verify.

Status vocabulary: WORKS = wired ribbon -> tool -> event -> Command -> result AND a test exercises it; PARTIAL = wired but with the stated gaps; PLACEHOLDER = a ribbon button / icon exists, clicking it only prints "X is not implemented in this UI prototype" (main.rs:495); ABSENT = nothing in the code.

## 0. Headline findings (read this first)

1. **The ribbon is mostly a façade for MEP.** Of 21 HVAC buttons 8 are wired, of 22 Plumbing buttons 7, of 20 Electrical buttons 3 (computed by diffing the ids in ribbon.rs:56-102 against the `run_command` match arms at main.rs:410-495). Not wired: every fitting, damper, flex duct, air terminal/diffuser/grille, fan, VAV, chiller, cooling tower, pump, valve, backflow, hanger/support, plumbing fixture, sprinkler, drain, cleanout, cable tray, conduit, raceway, junction/pull box, lighting fixture, switch, socket, device, panel, transformer, generator, disconnect, clash, interference check, link model. All fall to `_ => message "... is not implemented in this UI prototype"` (main.rs:495).
2. **The component library contains exactly one MEP family: "Fan coil unit, ducted"** (`openbim_family::library::all()` = handle, door, window, arched door, fan_coil; crates/family/src/library.rs:309-311, fan_coil at :316). There is no AHU, air terminal, VAV, pump, chiller, plumbing fixture, sprinkler head, luminaire, switch, socket or panel family. The "AHU" and "Component" buttons both open the same fan coil (main.rs:464). Nothing in apps/desktop loads a family or a type catalogue (no caller of `Catalogue::from_text` or of any family loader in apps/; `load_family` exists only as an icon, icons.rs:112). Families are Rust code, not user data. So "where does equipment come from" = hard-coded.
3. **The only fan coil is not editable in its flows/sizes from the mouse.** Properties only exposes instance-scope inputs (export.rs:57-65 filters `Scope::Instance`; panels.rs:773-776). In the fan coil only length, depth, height, with_return_duct are Instance; air_flow (0.1 m3/s), water_flow, duct_w/h, pipe sizes, voltage, power are Type-scope (library.rs:322-342) and the family defines no types (no `types:` in fan_coil), and Edit Type (type_editor.rs) is for wall types only. A user cannot change the unit's airflow, connector sizes or kW with the mouse.
4. **Systems are groups of equipment, not of ducts/pipes; there are no air terminals to put in them.** `MepSystemDef` = name + System enum + member family instances + optional base (crates/document/src/mep.rs:~97-105). The only members that can exist are fan coils. Layout joins like-typed connectors together regardless of flow direction (no use of `flow_dir` except to choose the base; layout.rs:115-140).
5. **Compute is by System type, not by system object, and needs hand-marked End Points and user-typed catalogues.** It ignores `MepSystemDef` (compute.rs:~118-122 filters runs by `system_of_run == s.system`). Source must be a hand-marked open run end; terminals are hand-typed demands (or "from the connector it meets" for the fan coil). The size catalogue, loading-unit curve and electrical cable tables are text boxes (optionally CSV file) that are NOT saved with the model (not in native.rs) and Manage > MEP Settings sizes are not used by Compute.
6. **Electrical is an abstract single-line tree, not Revit electrical.** "Electrical Node" (Source/Board/Load) and "Cable" live in `MepData.elec_nodes/elec_cables` (crates/document/src/elec.rs), are not elements (cannot be selected with Select, no Properties, no 3D, no schedule, not IFC entities - only in the app's own records inside the IFC). No panels-as-objects, no devices, no luminaires, no circuits, no panel schedules, no cable tray/conduit tools.
7. **Architecture dependency is absent.** No Link Model (button unwired), no copy/monitor, no Space/Zone (only Room, which is not exported as IfcSpace, export.rs:198,291 `rooms: vec![]`), Import IFC merges and drops IfcDoor/IfcWindow/IfcSpace/curtain walls (reader.rs:135-153 member list), wall penetrations for ducts/pipes are not produced by the app (export.rs:290 `wall_penetrations: vec![]`), no clash detection (main.rs:642 text only).
8. **Several "done" claims in the docs hold; several are stale or optimistic** - see section 11.

## 7. The Compute button, per system (what it does and what it needs)

Wiring: ribbon `compute` (HVAC, Plumbing, Analyze) -> `self.compute.open = true` (main.rs:422) -> `compute_window` (compute_ui.rs:~224) -> Compute button -> `run_compute` (compute_ui.rs:215) -> `refresh_equipment_ends()` then `compute::compute_system` (crates/document/src/compute.rs). `elec_compute` -> separate window (elec_ui.rs) -> `compute_elec::compute_electrical` (crates/document/src/compute_elec.rs).

Prerequisites the user must satisfy with the mouse and keyboard:
- Give the runs the right System (drawn runs already carry it: mep.rs:549; or Compute > "Give the selected line this system", compute_ui.rs:~308).
- Mark exactly ONE Source on an open run end (End Point tool, Source). Fewer/more: `NoSource` / `MoreThanOneSource` (compute.rs).
- Mark each Terminal with a demand: flow l/s; power kW + delta-T; loading units; sprinkler K + min flow; or "from the equipment connector it meets" (kind 4; only fan-coil connectors exist). Loops are refused (`ComputeError::Loop`, "Rings are not computed yet").
- Type or load (CSV) a size catalogue: `label,diameter` or `label,width,height` (compute_ui.rs:78-96). With an empty catalogue every non-locked branch fails `NoSize` (calc/tree.rs:228) unless "Keep the drawn sizes" is ticked. MEP Settings' diameter/width lists are NOT used here.
- Fluid: Water/Air preset buttons set density/viscosity/specific heat/roughness only; the System combo does not change the fluid, and `max_velocity` stays at the default 1.5 m/s (compute_ui.rs:69), so a Supply Air duct computed without touching presets uses water properties and a 1.5 m/s limit (trap).
- Fitting K coefficients typed (defaults 0.3/0.1/0.5/0.5, `ComputeDialog::default`).

Behaviours that look wrong versus Revit / risky:
- `end_point_click` clears any `equip_links` on the clicked port before adding the new end point (compute_ui.rs:132). Marking a Source on a duct end that is joined to equipment (or a typed Terminal on one) silently unjoins it from the unit; only kind 4 re-adds the join. After Generate Layout all trunk ends are joined to equipment, so the normal "mark the source" step breaks the join (reading of the code; no test covers Source on a joined end).
- Moving equipment does not drag its ducts until Compute (or `refresh_equipment_ends`) is pressed; moving a joined duct is refused (edit.rs:141).
- Compute tables are not persisted with the model (no catalogue/curve/cable-table in native.rs), so each session re-enters them; results are not stored either (report is session state, `rev != now` banner).
- Equipment-driven demand uses the connector's fixed airflow (finding 3).
- Compute ignores the user-named systems (MepSystemDef); it works on the `System` enum, so two separate CHW loops in one model are one computation (and fail with `MoreThanOneSource`).

## 12. Mouse-simulating tests; can an end-to-end "AHU -> terminals -> layout -> sizing" test be written?

Existing tests with real pointer events (egui `RawInput` through `show()`): model_view.rs:1343, :1367 (duct/pipe), and the many architecture ones (wall, grid, beam...). Tests with a ribbon click: none for MEP (`run_command` is called directly). Tests of MEP chains by method call: systems_ui.rs:333 (place 3 fan coils -> select -> create CHW system -> Generate Layout -> change trunk size -> Finish Layout -> joins -> undo), :448 (ducts), elec_ui.rs:636 (place unit -> load from connector -> move unit -> refresh -> duct to connector -> end point from connector), compute_ui.rs:432 (draw duct with branch -> End Points -> assign system -> Compute -> Apply sizes -> undo).

No test covers: ribbon button hit, Family placement through a pointer click for the fan coil (placement is by `family_click`/`place_family`), the egui OK/Finish Layout/Compute buttons, a Compute after Generate Layout, Source marked on a joined end, or any IFC check of a generated layout.

Could it be written with the current harness? Mostly yes, in two levels:
- Method level (works today): `Desktop::sample()`; `run_command("ahu")`; `family_click` x N (or `click()` in the plan after setting `app.view=Plan`, `app.slab_offset_mm`); `select_many`; `open_create_system(false)` + `confirm_create_system`; `open_generate_layout` + `finish_layout`; `choose_tool(Tool::EndPoint)` + `end_point_click(level, pos)` for the source and each terminal (kind 4 for fan coils); set `app.compute.system/density/.../catalogue/max_velocity` explicitly; `run_compute`; `compute::apply_sizes`; assert sizes, IFC counts, `undo_document`. This would reveal the Source-unjoins-equipment behaviour (section 7) and the System::Other export issue.
- Pointer/ribbon level: the harness can send `PointerMoved/PointerButton` to the viewport, but it has no widget finder, so clicking ribbon buttons or window buttons (OK, Finish Layout, Compute) needs either egui_kittest/AccessKit (not a dependency, grep found none) or computing rects from a previous frame's `Response`. Ribbon buttons are drawn with `allocate_exact_size` (ribbon.rs big_button) at 64x66 px in a scroll area, so a test could compute positions deterministically, but none does.
- The scenario cannot be a real AHU -> terminals test because no AHU or terminal family exists; it would be fan coils only (like the current tests).

## 15. Things that look wrong vs Revit (collected)

- Marking an End Point as Source/Terminal on a run end joined to equipment drops the equipment join (compute_ui.rs:132).
- Moving a joined duct/pipe is refused (edit.rs:141); in Revit connected elements follow. Equipment move does not stretch connected runs until Compute.
- Layout and drawing ignore connector flow direction (fan coil supply outlets are tied together).
- Fan coil supply connector at fixed type values; airflow not editable.
- "AHU" button places a fan coil; the Offset box for components is the slab/ceiling offset field shared across tools.
- Elbows at any angle; no snap-angle UI; clicks snap only to a 50 mm grid and not to connectors/walls in the Duct/Pipe tool (while other tools got Revit-style snaps).
- Bend with a size change refused instead of auto-fitting.
- Compute: air duct uses water defaults unless the Air preset is pressed and velocity limit retyped; sizes lists in MEP Settings ignored; tables not saved; ignores named systems; sanitary/vent run as pressurised.
- IFC: run with no fitting exports System::Other; user system names not exported as IfcSystem; fittings are straight stubs; equipment in IFC2X3 dropped; rooms not exported.
- Electrical nodes/cables are not model elements (no Select, no Properties, no 3D, no schedule).
- Wall penetrations by MEP never created in the app though the engine exists.
- Tags show names, not parameters.
